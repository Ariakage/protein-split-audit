# Security policy

## Supported versions

Security fixes target the latest tagged release and, when applicable, the current development
branch. Older release lines may receive documentation-only mitigations.

## Reporting

Do not place secrets, private paths, unpublished protein records, access ledgers, or exploit details
in a public issue. Until GitHub private vulnerability reporting is enabled for this repository,
send a concise private report to the maintainer address listed in `pyproject.toml` with:

- the affected version and component;
- a minimal synthetic reproduction;
- the expected impact;
- whether the issue exposes credentials or controlled artifacts; and
- any suggested mitigation.

Use a public GitHub issue only for non-sensitive hardening suggestions. Security reports do not
authorize Test access, formal replay, or disclosure of controlled research artifacts.

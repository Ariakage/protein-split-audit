# ProteinSplitAudit v0.1.0 post-release correction

> This report records the correction before it was packaged as the v0.1.1 corrective tag. The
> later version, commit, tag, and release-maintenance results are recorded in
> `docs/releases/v0.1.1.md` and the repository history.

## Why this correction was needed

The annotated `v0.1.0` tag and the public GitHub Release were published on 2026-07-14, but the
tagged README and changelog still said that no tag or release existed. The GitHub Release body and
`docs/releases/v0.1.0.md` also contained the pre-release readiness audit, which recommended
against publication at that time.

At the time of this audit, the patch corrected the public status without changing the `v0.1.0`
tag, project version, package behavior, license texts, or GitHub Release state. It preserved the
old readiness report as a historical audit. The reviewed correction was subsequently assigned
version 0.1.1.

## Statements corrected

The current README, changelog, and release notes no longer state that the repository is
unpublished, that no tag or GitHub Release exists, or that v0.1.0 is waiting to be published.

The new release notes distinguish the published software from a benchmark dataset. They retain
the incomplete acceptance criteria as known limitations rather than implying that publication
completed them.

## Verified v0.1.0 features

- Python 3.12 packaging with uv and a locked dependency set.
- `psaudit --version` and `psaudit doctor`.
- `psaudit data download`, `psaudit data build`, and `psaudit data profile`.
- A validated pilot configuration.
- Paginated UniProtKB download with bounded retries, normalized TSV content, deterministic gzip,
  response-header filtering, and provenance.
- Complete single-EC validation, EC-level-2 mapping, sequence validation, and exact-sequence
  duplicate handling.
- Deterministically ordered local Parquet and FASTA outputs.
- Aggregate-only candidate profiles.
- Offline tests, Ruff, strict MyPy, pytest, GitHub Actions quality checks, and local uv builds.

## Verified known limitations

- `psaudit config validate` and `psaudit data run` are absent.
- Query validation rejects blank values but does not enforce all reviewed-bacterial query terms.
- Failed retry attempts are not persisted in a local attempt audit.
- EC and sequence rejections are counted in aggregate, with no per-record rejection table.
- EC parsing does not retain token-level outcomes, remove an optional `EC=` prefix, or enforce
  positive nonzero components.
- Sequence normalization does not remove internal ASCII whitespace.
- Download and build manifests mix run timestamps with deterministic content hashes.
- No GitHub Actions run is recorded for the tagged commit.
- The tagged commit tracks sequence-free JSON manifests, including an accession-level
  deduplication map. These files contain no protein sequences, but the detailed mapping should be
  reviewed against the repository's artifact policy before a future release.

Review and commit the documentation correction, then replace the GitHub Release body with

wheel or source distribution.

Suggested commit command:


Suggested command to update the existing GitHub Release notes:

```bash
gh release edit v0.1.0 --notes-file docs/releases/v0.1.0.md
```

No package upload command is needed because both package assets exist. To add the missing checksum
attachment safely, rebuild from the tag in a temporary worktree and upload only that checksum:

```bash
TAG_BUILD=$(mktemp -d)
git worktree add --detach "$TAG_BUILD" v0.1.0
(
  cd "$TAG_BUILD"
  uv build
  shasum -a 256 \
    dist/protein_split_audit-0.1.0-py3-none-any.whl \
    dist/protein_split_audit-0.1.0.tar.gz \
    > dist/SHA256SUMS
)
gh release upload v0.1.0 "$TAG_BUILD/dist/SHA256SUMS"
git worktree remove "$TAG_BUILD"
```

These commands are proposals only. This corrective task does not run them.

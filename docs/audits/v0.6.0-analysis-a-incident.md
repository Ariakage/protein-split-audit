## Root cause

The v0.5.0 prediction schema intentionally permits null nearest-neighbor fields for methods other
than Nearest Homolog. Only Nearest Homolog predictions carry a Boolean no-hit state and a nearest
identity. The initial v0.6.0 parser incorrectly required `no_hit` to be Boolean for all seven
methods before it joined the separately authenticated Nearest Homolog detail artifacts.

Synthetic fixtures had populated those fields for every method, so the mismatch was not exposed
before the formal session. The frozen data was valid; the v0.6.0 input-normalization assumption
was not.

## Prospective corrective action

Revision r1 is limited to these changes:

1. Non-Nearest-Homolog predictions must have null `nearest_train_identity` and `no_hit` values.
2. Nearest Homolog predictions retain the strict hit/no-hit validation and must agree with the
   authenticated Nearest Homolog detail artifact.
3. Every method receives its analysis stratum from that authenticated detail artifact after exact
   private-row alignment.
4. New formal sessions use `analysis-r1-a` and `analysis-r1-b`, with distinct output and ledger
   identities; the consumed initial session is never retried.
5. All corrective tests use synthetic fixtures. Generation A5 performs no frozen row-level
   analysis and creates no active r1 attestation.

The scientific protocol, frozen inputs, predictions, cohort, splits, metrics, bins, bootstrap
rules, comparisons, privacy thresholds, and public artifact allowlist remain unchanged. Formal r1
execution requires a new permanent OWNER approval and an attestation-only Commit B2.

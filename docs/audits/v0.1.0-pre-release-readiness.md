# ProteinSplitAudit v0.1.0 release-readiness report

> This document is a historical pre-release audit. It records the state before the v0.1.0 tag and
> GitHub Release were published. It is not the current release note.

- Version: 0.1.0
- Release date recorded in metadata: 2026-07-14
- Publication: none; local development commits may exist, but no push, tag, or GitHub Release was created
- Readiness: **blocked until the acceptance gaps are fixed and a maintainer reviews the result**

## What the package contains

The source distribution and wheel contain the project diagnostics, paginated UniProtKB
downloader, candidate EC and sequence checks, exact-sequence conflict handling, deterministic
local Parquet and FASTA construction, aggregate profiling, provenance hashes, and offline tests.

The package does not choose final EC classes or create splits, features, or models. It makes no
claim about leakage or benchmark performance, and it does not publish a candidate dataset.

## Acceptance review

| Criterion in `docs/plans/v0.1.0.md` section 19 | Result | Evidence or remaining gap |
| --- | --- | --- |
| The complete CLI contract, including `config validate` and four `data` subcommands, works from the installed wheel | **Fail** | The isolated wheel passes `psaudit --version` and `psaudit doctor`. `psaudit config validate` and `psaudit data run` are missing, and the `data` group contains only `download`, `build`, and `profile`. |
| Config validation is strict, enforces the reviewed-bacterial query and fixed candidate protocol, and resolves relative paths from the config | **Partial** | Tests cover unknown keys, endpoint restrictions, bounds of 50 to 1000 residues, the standard alphabet, single and complete EC flags, and relative paths. The schema does not enforce every reviewed-bacterial query token semantically. |
| Pagination and retries have complete local page and attempt records, with offline tests | **Partial** | Offline tests cover normal final-page completion, malformed and repeated links, missing records, bounded transient retries, headers, duplicate pages, and totals. Completed pages are recorded, but failed retry attempts are not saved in a local attempt audit. |
| Every record reaches one terminal accounting path and the profile counts reconcile | **Fail** | Synthetic aggregate counts reconcile, and duplicate and conflict membership is recorded. Invalid EC or sequence rows appear only in aggregate rejection counts, not in the required per-record terminal audit. |
| EC and sequence processing follows sections 9 and 10 exactly and contains no split or model behavior | **Partial** | Tests cover one complete EC annotation, level-2 mapping, strip and uppercase normalization, the standard alphabet, and length limits. There is no split or model code. The implementation lacks the plan's complete token-level EC outcomes and ASCII-whitespace cleaning contract. |
| Candidate, FASTA, detailed audit, and profile output is deterministic | **Partial** | Repeat tests cover deterministic Parquet, FASTA, JSON, and CSV content and ordering. The detailed per-record audit tables from the plan do not exist. |
| Deterministic content manifests are separate from timestamped local run provenance | **Fail** | Download and build manifests record source, configuration, artifacts, package, Git, Python, and lock hashes, but timestamps and content hashes remain in the same files. |
| Publication never overwrites a final artifact or leaves a partial one | **Pass** | Download, build, and profile publishing refuse existing targets and use staged atomic publication. Tests cover overwrite behavior. |
| Locked checks, offline tests, package build, and the network guard pass | **Pass locally** | `uv sync --locked`, Ruff, strict MyPy, 68 offline tests, and `uv build` pass. The autouse socket guard blocks real network access during tests. There is no CI result from a release commit because no release commit exists. |
| No unauthorized data, audit, benchmark result, commit, push, tag, or release is created | **Pass** | Worktree and wheel review found no prohibited artifact. Local commits are created only after explicit maintainer authorization; nothing is pushed, tagged, or released. |

Seven criteria are either partial or failed, so v0.1.0 is not ready to publish.

## Verification results

- `uv lock --check`: passed; 176 packages resolved and the project files agree.
- `uv sync --locked`: passed; the local package changed from 0.1.0.dev0 to 0.1.0.
- `uv run ruff check .`: passed.
- `uv run ruff format --check .`: passed; 22 files checked.
- `uv run mypy src`: passed; 11 source files checked.
- `uv run pytest`: passed; 68 tests.
- `uv build`: created the 0.1.0 source distribution and wheel.
- Isolated-wheel `psaudit --version`: reported `0.1.0`.
- Isolated-wheel `psaudit doctor`: passed overall and reported the dirty worktree as a warning.
- `CITATION.cff`: YAML, version, and date checks passed.
- Wheel inspection found only package code and distribution metadata, with no data or model
  artifact.
- The license texts in `LICENSES/` were unchanged.

The review could not verify CI from a release commit, because no commit was authorized. It also
found no human approval for the remaining protocol differences and no authorized real UniProt
download or candidate/profile artifact review.

## Repository and artifact review

Git tracks no raw or processed UniProt data under `data/raw/`, `data/interim/`, or
`data/processed/`. There is no profile output in `results/runs/profile-pilot/`, so no aggregate
file was copied to `results/released/v0.1.0/`.

The wheel contains no Parquet, FASTA, model weight, embedding, notebook cache, environment, or
file with a secret. The TSV fixtures are synthetic project-authored test data, as documented in
`tests/fixtures/README.md`; they are not UniProt records.

`dist/` remains ignored. A pre-existing 0.1.0.dev0 wheel is not a proposed release artifact.
Authorized development work may be recorded in local commits. The branch remains local unless a
maintainer separately approves a push.

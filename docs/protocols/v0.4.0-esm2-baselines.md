# v0.4.0 frozen ESM-2 embedding baseline protocol

## Purpose and boundary

This protocol adds frozen ESM-2 representations to the cohort and four splits published in
v0.2.0 and used by the v0.3.0 classical baselines. It evaluates two representation models with
one fixed linear probe, producing eight Validation cells:

- `esm2_35m` and `esm2_150m`;
- Random, Cluster70, Cluster50, and Cluster30.

The cohort, labels, and split assignments are unchanged. Model selection, hyperparameter search,
fine-tuning, Test evaluation, and benchmark claims are outside this release. The experiment
configuration keeps `real_test_access_authorized: false`. Extraction, fitting, and reporting may
read only Train and Validation rows; all Test-access counters must remain zero.

The model and tokenizer use the same full 40-character revision. A mutable branch, tag,
abbreviated revision, or mismatched repository is invalid. Downloads occur only through
`psaudit embedding fetch`; every other command is offline.

Each canonical snapshot contains exactly these files:

- `config.json`
- `model.safetensors`
- `tokenizer_config.json`
- `special_tokens_map.json`
- `vocab.txt`

The actual file set must equal this allowlist. Missing, extra, or symlinked canonical files fail
verification. The snapshot manifest records the relative path, byte size, SHA-256, repository,
revision, and `downloaded_at_utc` for each file. Snapshot identity excludes acquisition time and
binds the remaining fields. The local weight bytes must match the approved SHA-256 above.

Formal loading uses `transformers.EsmForMaskedLM` with `local_files_only=True` and
`use_safetensors=True`. Missing, unexpected, mismatched, or errored keys are forbidden. The full
model is put in evaluation mode, all parameters have gradients disabled, and inference runs under
`torch.inference_mode()`. Representations come from the loaded model's `.esm` encoder; the masked
language-model head is not called.

## Tokenization, batching, and pooling

Input sequences remain 50–1000 residues. Truncation is disabled, so an out-of-range sequence or
tokenization inconsistency fails instead of being shortened.

The representation is the final encoder layer, averaged over residue tokens only. BOS, EOS,
padding, and every other special token are excluded. The result is stored as dense `float32`.

Records are sorted by tokenizer-encoded length, then sequence SHA-256. Greedy batching uses the
actual padded cost:

`padded token cost = batch size × maximum encoded length in the batch`

Encoded length includes the special tokens sent to the model. The budgets are 4096 padded tokens
for `esm2_35m` and 2048 for `esm2_150m`. A single sequence above the batching budget is isolated,
but a sequence above the model or 1000-residue limit fails. Manifests record batch count, maximum
batch size, maximum encoded length, maximum and mean padded-token cost, padding efficiency, and
any over-budget singleton count. Formal runs require that last count to be zero. Cache rows are
restored to canonical cohort-manifest order.

## Formal runtime and cache identity

Release-eligible execution is fixed to Darwin/arm64, Python 3.12, CPU, `float32`, eight PyTorch
intraop threads, one interop thread, and deterministic algorithms. MPS is allowed only for local
development and its artifacts are never release-eligible. The program does not silently choose a
different device.

The cache key binds the model and tokenizer snapshots, embedding configuration, dependency
versions, upstream cohort and split hashes, selected Train/Validation records, device, dtype, and
thread policy. A cache contains `embeddings.npy`, `index.parquet`, and a deterministic manifest;
writers are atomic and refuse replacement. Validation rehashes every component and verifies row
alignment before reuse. No all-cohort or Test-bearing cache is permitted.

## Linear probe and evaluation

`StandardScaler` is fitted on Train embeddings only. Its stored state binds the Train accession
and row-index identities. Logistic Regression retains the v0.3.0 settings: `lbfgs`, L2,
`C=1.0`, balanced class weights, `max_iter=5000`, `tol=0.0001`, intercept enabled, and
`random_state=42`. A convergence warning is fatal. Metrics and label order follow the frozen v0.3
evaluation contract and are calculated on Validation only.

The formal matrix is exactly two models by four splits. Completion markers bind every local cell
artifact and record zero Test sequences, labels, and metrics. Resume is allowed only after full
artifact-set and hash verification.

## Replay and reviewed aggregate previews

A same-platform formal replay must use the same hardware category, Python and locked dependencies,
snapshot and input hashes, configuration, CPU/dtype/thread policy, and deterministic environment
identity. Embeddings, indexes, scaler and classifier manifests, predictions, metrics, and other
deterministic files must be byte-identical. Rowwise predictions must agree and replay difference
must be zero. A mismatch blocks release; it cannot fall back to tolerance-based acceptance.

Cross-platform comparison is diagnostic and never release-eligible. It reports
`max_absolute_difference`, `max_relative_difference`,
`number_of_values_outside_tolerance`, `prediction_disagreement_count`, and `metric_difference`
using `rtol=1e-5` and `atol=1e-6`.

Only six sequence-free preview files may be considered for later publication: ESM Validation
summary and per-class tables, the verified classical-versus-ESM table, embedding feature schema,
model snapshot hashes, and an environment summary. They contain no sequences, accessions,
predictions, Test fields, secrets, or private paths. Model assets, embeddings, fitted estimators,
per-record outputs, logs, and complete run directories remain ignored.

## Upstream restoration and freeze flow

Before model access, the restoration gate verifies eleven frozen v0.3 inputs byte-for-byte: the
cohort Parquet/content manifest/FASTA and four split Parquet/content-manifest pairs. It also checks
schemas, row counts, cohort–FASTA alignment, Train/Validation membership, accession-set hashes,
the v0.3 attestation, a fixed Git commit, the lock hash, and a clean tree. It never regenerates or
repairs a split. The audit is recorded in
`docs/audits/v0.4.0-frozen-input-restoration.md`.

The release workflow uses three separately reviewed commits:

1. Generation Commit A freezes code, tests, configs, protocol, notices, and sanitized snapshot
   manifests. It contains no formal results or attestation.
2. Attestation Commit B is allowed only after a permanent maintainer-authored approval URL binds
   Generation A and every frozen identity.
3. Release Commit C follows two byte-identical clean formal replays, aggregate review, and explicit
   Test-denial review. Only then may release-facing metadata and reviewed aggregates change.

CI installs the locked optional ESM dependencies but remains offline and weight-free. It uses
fake adapters and a tiny randomly initialized local ESM model. It does not fetch snapshots, run
the real cohort, or generate formal results.

## Known limits

This pilot covers one small cohort and two frozen checkpoints with one pooling and classifier
protocol. It does not establish broad model quality. The key limitation is simple:
pretraining-corpus contamination is not audited. Test proteins cannot be claimed unseen during pretraining.
Sequence-level split
controls do not prove independence from pretrained data, homologs outside the cohort, annotation
bias, or organism-specific sampling effects.

# ProteinSplitAudit v0.5.0 Frozen Test Evaluation and Pilot Study Protocol

## Status and authority

This document freezes the intended v0.5.0 Test-evaluation design. It does not authorize Test
access by itself. Development, CI, documentation review, and Generation Commit A remain in the
closed state:

```yaml
real_test_access_authorized: false
```

Real Test access requires a later owner-authored permanent approval that binds the clean
Generation Commit A and every identity in this protocol, followed by the machine-readable
`docs/attestations/v0.5.0-test-freeze.yaml` in Attestation Commit B. Until that file exists and the
complete fail-closed gate verifies from a clean detached B worktree, no command may parse,
materialize, transform, predict, or evaluate the real Test partition.

This protocol does not authorize a commit, push, approval comment, attestation, formal run, tag,
Draft Release, or public Release.

## Purpose and research boundary

v0.5.0 is the first controlled opening of the frozen Test partition. It asks an engineering and
pilot-study question: after cohort, split, method, model, and Validation choices are frozen, can the
seven approved methods be fitted on Train, evaluated once on Test, replayed mechanically, and
reported with complete provenance and aggregate uncertainty without Test-driven revision?

The formal matrix contains exactly seven methods and four split strategies, or 28 Test cells. No
new method or tuning decision is permitted:

1. Majority Class;
2. Sequence Length plus Logistic Regression;
3. amino-acid composition plus Logistic Regression;
4. fixed 3-mer relative frequency plus Logistic Regression;
5. Nearest Training Homolog;
6. ESM-2 35M residue-mean embedding plus frozen linear probe;
7. ESM-2 150M residue-mean embedding plus frozen linear probe.

The splits are Random, Cluster70, Cluster50, and Cluster30.

This release does not add ESM-2 650M or another protein model, change pooling, fine-tune ESM,
alter Logistic Regression or Nearest Homolog parameters, change the cohort or splits, use
Validation as extra training data, tune from Test, perform repeated scientific seeds, build a
dashboard, submit a paper, or make a final main-study claim.

## Test authorization gate

The machine-readable attestation is strict and records the project/release/type, clean Generation
A, software version 0.5.0, Python/runtime, v0.5 protocol/config/lock/dependency-diff hashes, every
upstream identity above, exactly 28 cells, exactly two sessions, the approved statistical rules,
`real_test_access_authorized: true`, approver, actual UTC approval time, owner association, and a
permanent GitHub PR/Issue comment URL.

Generation A, v0.5 protocol/config/lock/report, and Attestation B hashes do not yet exist at this
documentation stage. They must be computed from their final bytes and bound by permanent approval;
the project must never predict or insert synthetic identity values.

Before any Test projection, the gate verifies:

- attestation schema, release, Test-specific type, true authorization, and permanent approval URL;
- clean Git state and exact Attestation Commit B execution identity;
- B's sole parent equals approved Generation A and the A-to-B diff contains only the attestation;
- protocol, config, lock, dependency-diff, and source hashes;
- cohort, FASTA, split, method, and model snapshot hashes;
- canonical Darwin/arm64, Python 3.12, CPU float32, 8/1 PyTorch thread runtime;
- MMseqs2 and ESM dependency versions;
- absent/internally consistent output, cache, access-ledger, and incident paths;
- formal sessions exactly `run-a` and `run-b`.

Every function capable of reading Test receives a verified authorization capability, not a boolean
flag. v0.3/v0.4 Validation attestations and legacy `finalize-test` commands can never grant access.
Formal execution is offline; approval metadata is verified before B and then validated from frozen
bytes without a GitHub request.

## Session consumption and incident policy

Preflight failure does not consume a session while no Test file has been opened, materialized, or
read. Examples include wrong attestation/hash, dirty Git, dependency mismatch, missing input,
insufficient disk space, or runtime failure.

Immediately before the first Test data read, the runner atomically records at least:

| Field | Required value |
|---|---|
| `session_id` | the selected formal session, exactly `run-a` or `run-b` |
| `test_session_status` | exactly `consumed` |
| `test_access_started_at_utc` | the real access-transition time as an RFC 3339 UTC timestamp |

Once written, the session is consumed even after a crash, power loss, disk failure, cell failure,
missing aggregate, or absence
of human inspection. The marker is append-only and cannot be deleted or rewritten to restore an
allowance. Only Run A and Replay B are authorized by default; Run C does not exist.

A failed consumed session blocks aggregate and release. Its ignored incident report records the
session, failure stage, access-start UTC, last verified hashes, sanitized exception class, and
whether partial results were viewed. It contains no sequence, accession, prediction, or private
path. A replacement requires a protocol revision and new permanent maintainer approval URL.

## Train-only fit and delayed Test evaluation

Each session projects each split once into an immutable Train/Test bundle shared by its seven
methods. The data flow is fixed:

```text
Frozen Train sequences and labels
  -> fit feature preprocessing / scaler / classifier / nearest target database
Frozen Test sequences without labels
  -> transform / query / predict exactly once
Sealed complete prediction identity
  -> load frozen Test labels
  -> evaluate and aggregate
```

Validation is excluded from fitting, transform, prediction, and evaluation. Test labels are not
available to feature extraction, scaler/classifier fitting, class weights, majority selection,
nearest-neighbor database construction, ESM extraction, prediction, configuration, method
selection, or error handling. A cell must seal exactly 66 unique Test predictions with matching
sequence hashes before the evaluator may project Test labels.

Detailed Test predictions, scores, correctness, nearest neighbors, features, embeddings, fitted
objects, per-run confusion intermediates, logs, access ledgers, and incidents remain local and
ignored. Only the sanitized aggregate confusion table defined below is public.

## Evaluation metrics

Primary metrics:

- Macro-F1;
- Balanced Accuracy, calculated as macro recall over the frozen label order.

Secondary metrics:

- Overall Accuracy;
- Macro Precision;
- Macro Recall;
- per-class Precision, Recall, F1, and support;
- fixed-order confusion matrix;
- prediction coverage;
- training time, prediction time, and sampled peak resident memory.

Nearest Homolog additionally records hit count/rate, no-hit count/rate, fallback count,
no-hit-correct count, and nearest-identity count/minimum/median/mean/p90/p95/maximum. Empty accepted
hit sets keep count zero and serialize distribution statistics as null.

Timing and memory are run-specific provenance, not deterministic content. Public deterministic
metric tables do not mix them with reproducible score identities. The environment summary may
report both sessions' observations with an explicit run-specific marker and no performance claim.

## Group-aware bootstrap and comparisons

Every v0.5 Test statistic uses the frozen v0.2 Cluster30 discovery component as its universal
resampling unit. Component IDs come from the frozen Cluster30 discovery graph; they are never
recomputed in v0.5 and never replaced by accession or a split-specific group. Every Test row must
map to exactly one component. A missing, duplicate, or hash-mismatched mapping blocks formal Test.

The statistical definition is fixed:

```yaml
bootstrap:
  unit: cluster30_discovery_component
  iterations: 2000
  confidence_level: 0.95
  interval_method: percentile
  lower_quantile: 0.025
  upper_quantile: 0.975
  seed: 2026
```

Each replicate samples Test-set component blocks with replacement and includes every Test record
in each sampled block. Fixed-label metrics retain a replicate even if a sampled draw omits a class,
using `zero_division=0`; the formal valid-repeat count is therefore 2,000. Reports include unit,
component count, requested/valid repeats, seed, point estimate, and lower/upper bounds. v0.5 does
not add BCa intervals, normal approximations, broad p-value testing, or post-Test method selection.

Within one split, methods use the same component draws for paired comparisons. The five directed
comparisons are:

- ESM-2 35M minus AAC;
- ESM-2 35M minus 3-mer;
- ESM-2 150M minus AAC;
- ESM-2 150M minus 3-mer;
- ESM-2 150M minus ESM-2 35M.

They are called absolute metric differences, not significant improvements.

For each method, the Macro-F1 generalization gaps are Random minus Cluster70, Random minus
Cluster50, and Random minus Cluster30. Because Test membership differs, the two split-specific
component streams are independent. These comparisons must never be described as paired.

## Formal replay

Run A and Replay B execute automatically and consecutively from the same clean B, command,
platform, lock, inputs, snapshots, configuration, seed, and thread policy. B starts from an
independent empty feature/embedding/MMseqs2/model cache namespace and cannot reuse A artifacts.

Both runs require all 28 cell IDs exactly once. Deterministic configurations, input/model
manifests, features/embeddings and indexes, fitted-state manifests, predictions, labels joined for
evaluation, metrics, per-class rows, confusion tables, nearest rows, bootstrap identities/results,
and completion manifests must be byte-identical. Stable environment fields must match.

UTC timestamps, timings, peak memory, host paths, process IDs, and logs are enumerated run-specific
fields and are excluded from byte identity. No tolerance-based formal fallback exists. Eligibility
requires zero prediction disagreements, zero metric/statistical differences, zero deterministic
mismatches, and `replay_difference=0`. Any mismatch sets `BLOCK AGGREGATE` and `BLOCK RELEASE`.


`confusion_matrices.csv` is long-form and has exactly these columns:

```text
method,split,true_label,predicted_label,count,row_fraction
```

It contains all 25 frozen label pairs for every method/split cell, or 700 rows. `count` is an
integer. For each method, split, and true label, counts equal class support and
`row_fraction = count / support`; fractions are finite, lie in `[0,1]`, and sum to 1 within
floating-point tolerance. Rows sort by frozen method, split, true-label, and predicted-label order.

Public files may contain class-level counts and metrics only. They must not contain accession,
sequence, record-level prediction/confidence/correctness, per-query nearest-neighbor information,
error examples, embeddings, models, scalers, caches, logs, local paths, host names, credentials,
cookies, tokens, or secrets. Structured and raw-byte privacy scans are release gates.

## Interpretation limits

This is a controlled Test pilot on one 442-record, five-class E. coli K-12 cohort with one frozen
seed and seven fixed methods. Confidence intervals describe component-resampled uncertainty within
this pilot; they do not establish population-wide performance. Absolute differences are not
automatically significant, causal, or transferable.

Sequence-level grouping does not establish independence from ESM-2 pretraining data, homologs
outside the cohort, organism-specific sampling, or annotation bias. v0.5.0 results cannot be
presented as a definitive protein-enzyme benchmark, a finished main study, or a final paper
conclusion.

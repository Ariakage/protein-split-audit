## Frozen presentation rules

The revision changes layout and labeling, not scientific content:

- Macro-F1 uses four split panels in a fixed 2-by-2 layout.
- Random-minus-cluster gaps use three fixed comparison panels.
- identity and length summaries use one panel per split with short, fixed bin labels;
- the per-class figure keeps the frozen EC level-2 class order;
- Nearest Homolog counts, rates, identity or coverage, and accuracy differences appear in separate
  panels so incompatible units never share an axis;
- the seven methods keep their protocol order and deterministic colors;
- confidence intervals are rendered only when the authenticated table supplies them;
- suppressed or under-supported cells are omitted, never plotted as zero and never represented by
  repeated `NA` bars;
- output filenames, PDF metadata, sorting, fonts, and layout are deterministic;
- an existing output directory is never overwritten.

Only synthetic fixtures may be used while implementing or testing these rules. Presentation
choices must not be tuned by reading row-level Test artifacts or rerunning the analysis.

## P1 and post-commit regeneration procedure

Presentation Commit P1 contains only the figure-generator change, synthetic tests, and this
human-readable protocol. It contains no regenerated PDF and no formal result.

After P1 is clean and all required checks pass, the six PDFs may be generated into a new ignored
candidate directory from the exact CSV inventory above. The command is limited to the reporting
surface:

```bash
uv run --locked psaudit report figures \
  --input-dir results/runs/v0.6.0-analysis-r1-aggregate-review \
  --output-dir results/runs/v0.6.0-release-candidate-r2/figures
```

The candidate must contain the approved 19-file public allowlist, pass the release-bundle and
privacy validators, and preserve the non-PDF public files byte for byte. Each PDF must be rendered
for human visual review, checked for clipping, overlap, unreadable labels, misleading axes, and
mixed units, then hashed. The source CSV hashes and protected-evidence hashes must be checked again
after generation.

## Stop condition

After P1 and the six regenerated PDFs have been reviewed and hashed, work stops. A new permanent
GitHub comment from an `OWNER` must explicitly approve P1, the ten source CSV hashes, and the six
new PDF hashes before any v0.6.0 release commit, tag, or GitHub Release is prepared.

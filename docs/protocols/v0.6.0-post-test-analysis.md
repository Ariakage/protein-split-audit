# ProteinSplitAudit v0.6.0 Post-Test Analysis and Robustness Audit Protocol

## Status and authority

This protocol freezes how v0.6.0 may explain the already completed v0.5.0 Test pilot. It does not
authorize access by itself. Generation Commit A contains code, tests, configuration, and this
document, but no attestation and no formal analysis output.

Formal access later requires a permanent maintainer approval and an attestation that states:

```yaml
new_test_inference_authorized: false
frozen_test_output_analysis_authorized: true
```

No model is trained, loaded, or executed. No Test inference is run. The cohort FASTA is not read.
Features, embeddings, fitted estimators, raw sequences, and MMseqs2 are outside this analysis path.
Only the frozen v0.5 Run A predictions may become the canonical private input after authorization.
Run B is replay evidence only and is never concatenated, averaged, or treated as another sample.

## Pilot boundary

The subject is the released five-class, 442-protein *E. coli* K-12 pilot and its four frozen split
strategies. The protocol explains those outputs; it does not establish a general protein benchmark,
a causal effect of homology, a universal model ranking, or statistical significance.

The seven methods remain, in order: Majority, Length Logistic, AAC Logistic, 3-mer Logistic,
Nearest Homolog, ESM-2 35M, and ESM-2 150M. The split order remains Random, Cluster70, Cluster50,
and Cluster30. The EC level-2 label order remains `2.7`, `3.1`, `1.1`, `2.1`, and `4.1`.

## Confirmatory analyses

The six questions below, their strata, metrics, and comparisons are pre-specified. They cannot be
reordered, merged, deleted, or amended after a formal row-level analysis session begins.

### RQ1 — Performance by split

For each method and split, report Accuracy, Balanced Accuracy, and Macro-F1. Generalization gaps
are Random minus Cluster70, Random minus Cluster50, and Random minus Cluster30. Test membership
differs across strategies, so these gaps use independent component-bootstrap streams.

### RQ2 — Nearest-Train identity

Each Test row enters exactly one nearest-Train identity stratum:

- `identity_00_20`: `[0.00, 0.20)`;
- `identity_20_30`: `[0.20, 0.30)`;
- `identity_30_40`: `[0.30, 0.40)`;
- `identity_40_50`: `[0.40, 0.50)`;
- `identity_50_70`: `[0.50, 0.70)`;
- `identity_70_100`: `[0.70, 1.00]`;
- `no_hit`: a separate state with no identity value.

Identity boundaries are fixed decimals, not data-derived quantiles. A no-hit row is not assigned
identity zero. Contradictory no-hit flags, non-finite identities, and identities outside `[0, 1]`
are input errors.

### RQ3 — Sequence length

Sequence length comes from the sequence-free frozen cohort metadata. Every Test row enters exactly
one inclusive bin:

- `length_050_199`: 50–199;
- `length_200_399`: 200–399;
- `length_400_599`: 400–599;
- `length_600_799`: 600–799;
- `length_800_1000`: 800–1000.

The protocol never substitutes split-specific quantiles or changes a boundary after seeing a plot.

### RQ4 — Per-EC-class generalization

For every frozen EC class and method, report class precision, recall, and F1 for Random and
Cluster30. The confirmatory gap is Random class F1 minus Cluster30 class F1. It is not called
“per-class Macro-F1”. A dominant wrong label is reported only when the group clears the fixed
support and privacy rules. A weak class is never removed from the pilot.

### RQ5 — ESM-2 versus classical features

The fixed, directed within-split comparisons are:

1. ESM-2 35M minus AAC Logistic;
2. ESM-2 35M minus 3-mer Logistic;
3. ESM-2 150M minus AAC Logistic;
4. ESM-2 150M minus 3-mer Logistic;
5. ESM-2 150M minus ESM-2 35M.

They are evaluated by split, identity bin, length bin, EC class, and component-size bin. Methods in
one comparison must have identical private row identities. The public wording is “absolute metric
difference” or “performance difference”. This protocol specifies no hypothesis test, so it makes
no claim of statistical significance.

Full-cohort Cluster30 discovery-component sizes use these approved bins:

- `component_singleton`: 1;
- `component_02_04`: 2–4;
- `component_05_09`: 5–9;
- `component_10_19`: 10–19;
- `component_20_plus`: at least 20.

### RQ6 — Nearest Homolog failure modes

For each split, summarize hit versus no hit, same-label versus different-label nearest neighbor,
nearest identity, query and target coverage, bitscore, and majority-fallback behavior. The no-hit
fallback count must equal the no-hit count. The fixed diagnostic comparison is ESM-2 150M minus
Nearest Homolog within each identity bin and no-hit. Neighbor accessions remain private.

## Exploratory analyses

Any newly noticed EC pattern, extreme-length behavior, confusion pair, or data-quality concern is
post hoc. Exploratory outputs remain private below `results/runs/v0.6.0-exploratory/` and carry all
three labels: `Exploratory`, `Post hoc`, and `Not pre-specified`. They cannot enter the v0.6.0
release, change this protocol, or justify selecting a model. Future publication requires a new
prospective protocol revision and approval.

## Metrics and resampling

Point estimates use the five frozen labels and zero-division value zero. The metrics are Accuracy,
Balanced Accuracy, and Macro-F1. Per-class output uses standard class precision, recall, and F1.

The bootstrap unit is the frozen Cluster30 discovery component. Formal intervals use exactly
2,000 draws, percentile 95% limits at 0.025 and 0.975, linear quantiles, and seed 2026. Components
are sorted before sampling; a sampled component contributes all of its rows once per occurrence.

Methods evaluated on the same split and stratum use paired component draws. Different Test sets
use independent, domain-separated draws even when some private row identities overlap. Diagnostic
seeds 3407 and 42 report endpoint and width drift only; seed 2026 remains primary and there is no
invented drift pass/fail threshold.

## Small-group and privacy rules

Rules apply in this order:

1. Fewer than 5 sequences or fewer than 3 Cluster30 components is privacy suppressed. Public
   counts render as `<5` or `<3`; exact counts and every metric are `NA`.
2. A privacy-safe group with fewer than 20 sequences reports exact aggregate counts but no metric.
3. A group with at least 20 sequences but fewer than 10 components reports a point estimate but no
   confidence interval.
4. At least 20 sequences and 10 components permits a point estimate and interval.

No interesting result relaxes these thresholds. Public files contain no accession, sequence,
per-record sequence hash, prediction row, neighbor accession, private path, or secret.

## Robustness audits

### Component influence

Within each split, rank components by Test-row count descending and component ID as a private
lexicographic tie-break. Recompute metrics from existing predictions after removing the largest
0, 1, 3, and 5 components. Public output records only ranks and aggregate removed counts.

### Class-balance sensitivity

On the same predictions and component draws, compare the direction of Accuracy, Balanced Accuracy,
and Macro-F1 for Random-minus-Cluster30 gaps and the five fixed method comparisons. There is no
class-balanced retraining, oversampling, synthetic data, or threshold tuning.

### Bootstrap stability

Repeat interval calculations at seeds 2026, 3407, and 42. Report shifts relative to seed 2026.
The extra seeds are diagnostics, not alternate formal conclusions.

### Prediction agreement

For AAC versus ESM-2 150M, 3-mer versus ESM-2 150M, and Nearest Homolog versus ESM-2 150M, report
both correct, both wrong, method A only correct, and method B only correct. No per-record disagreement
file or unplanned significance test is produced.

## Input authentication

Opaque SHA-256 checks run before row parsing. The gate binds the v0.5 protocol and attestation,
the released v0.5 Git object for `uv.lock`, both formal run inventories and ledgers, the exact
replay report, 28 prediction hashes, four Nearest Homolog detail hashes, sequence-free cohort
metadata, four split manifests, and the reviewed v0.5 aggregate. Run A and Run B counterparts must
be byte-identical for every analysis input.

After authorization, private joins require exactly 66 unique Test rows per method/split, exact
agreement of row identities and labels across methods, one cohort row, one matching split row, and
one non-empty Cluster30 discovery component. Errors expose only safe artifact and aggregate context.

## Two-run analysis replay

Formal Analysis A and immediate Analysis B run from the same clean detached Attestation Commit B,
locked environment, configuration, and frozen inputs. Both independently analyze canonical Run A.
No result is shown between sessions. Deterministic tables and PDFs must be byte-identical.

Run-specific UTC timestamps and host details are kept in ignored provenance files and excluded for
documented reasons. A failure after the first frozen prediction row is parsed consumes that analysis
session and requires incident evidence plus a prospective protocol revision; no Analysis C appears
automatically.

## Public release boundary

Only the 19 files listed in `configs/analysis/v060-post-test-analysis.yaml` may enter
`results/released/v0.6.0/`. Figures are generated from sanitized aggregate CSVs, never predictions.
The privacy scanner rejects record identities, sequence-like text, per-record formats, local paths,
secrets, small-group disclosure, unapproved files, and variable PDF metadata.

Formal analysis and release remain gated by three distinct commits: Generation A, an
attestation-only B after permanent maintainer approval, and Release C after exact replay and
scientific/privacy review. This protocol does not authorize a commit, push, tag, Draft Release, or
publication.
